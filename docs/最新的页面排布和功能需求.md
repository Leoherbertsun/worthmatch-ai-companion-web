# WorthMatch 新版四入口网页产品需求说明

> 版本：2026-05-15  
> 当前定位：先做一个可真实体验的响应式网页应用。桌面端优先呈现完整信息密度，移动端保留同一套交互逻辑并自适应，不再在网页里嵌一个手机外壳。

## 1. 产品结构

WorthMatch 新版保留四个一级入口：

1. **AI Agent**
2. **探索活动**
3. **消息**
4. **我的**

核心原则：

- 不沿用旧版多按钮、多页面、信息松散的网页逻辑。
- 以真实产品应用为目标，而不是概念展示页。
- 桌面端可以使用左侧导航和多栏布局，移动端切换为底部导航。
- UI 要克制、现代、干净，但细节要足够真实：状态、权限、附件、卡片、筛选、空闲信息都要有产品感。
- 动物 IP 暂时不作为主要设计约束，优先建立 WorthMatch 自己的视觉系统。

## 2. AI Agent

Agent 是用户进入 WorthMatch 的核心入口，负责把模糊愿望整理成可匹配结构。

需要具备：

- 历史对话列表。
- 新建对话。
- 底部输入框。
- 输入框左侧加号，包含照片、文件、位置、日程、语音、模板等入口。
- 输入框右侧语音/转写入口。
- 快捷 prompt，例如低压 city walk、不尴尬开场、从零建档。
- 用户发送自然语言后，AI 输出不只是文字，还要包含：
  - 思考过程
  - 待办事项
  - 标准化搭子卡片
  - 下一步可点击动作

典型流程：

1. 用户说：“我想周六下午找一个低压 city walk 搭子，最好能顺路喝咖啡。”
2. Agent 提取意图：低压 city walk / 咖啡搭子。
3. Agent 提取字段：时间、地点、人数、社交强度、边界。
4. Agent 生成卡片：标题、摘要、时间、地点、人数、标签。
5. 用户可以点击发布到探索、继续补充、生成开场白。

AI 语气：

- 中文，克制，有洞察。
- 每次最多问一个关键追问。
- 不过度拟人，不做夸张陪伴。
- 涉及线下时提醒公共场所、可退出、不暴露精确住址。

## 3. 探索活动

探索页用于冷启动阶段承载官方活动、系统提示、测试功能、用户组局和附近活动。

需要具备：

- 搜索框，可搜索活动、功能、搭子局。
- 分类切换：全部、官方、组局、测试、附近。
- 筛选面板：
  - 最新排序
  - 最近开始
  - 距离排序
  - 距离范围
  - 活动类型
- 活动卡片列表。

活动卡片字段：

- 标题。
- 官方/附近/功能/测试标签。
- 摘要。
- 时间。
- 地点。
- 距离。
- 人数。
- 标签。
- 展开详情。
- 参加/加入按钮。

详情弹窗需要包含：

- 活动完整说明。
- 活动流程。
- 加入前确认问题。
- 加入后可以带回 Agent 生成开场白、报名理由或边界说明。

可放入探索页的冷启动内容：

- WorthMatch AB Test 体验场。
- 周六低压 City Walk。
- AI Agent 共创桌。
- 90 分钟安静自习搭子。
- 个人档案卡新功能。

## 4. 消息

消息页参考微信、Instagram、WhatsApp Web 的成熟聊天结构，但要结合 WorthMatch 的匹配和权限逻辑。

需要具备：

- 会话列表，包括好友聊天和群聊。
- 搜索聊天或好友。
- 筛选：全部、未读、群聊。
- 最近消息、时间、标签、未读状态。
- 点击会话进入聊天。
- 聊天页顶部显示头像、昵称、在线/活动状态。
- 聊天输入框左侧加号。
- 消息加号菜单包含：
  - 照片
  - 文件
  - 位置
  - 日程
  - 语音
  - AI 润色
- 支持文本消息、系统匹配提示、位置卡片、活动待办卡片。

资料与权限：

- 点击聊天对象或“资料与权限”可看对方/群聊资料。
- 右侧信息栏展示：
  - 头像
  - 昵称/群名
  - 来源：来自 Agent 匹配或探索活动
  - 标签
  - 当前可见信息
  - 成员列表
  - 共享媒体、链接与文件
  - 共同活动记录
  - 资料可见权限

信息解锁逻辑：

- 未匹配：只能看公开标签。
- 匹配后：可看基础介绍和共同活动。
- 好友后：可看更多动态、活动足迹和自定义资料。
- 用户可在“我的”里控制可见范围。

## 5. 我的

“我的”页是用户主页和设置入口，参考淘宝个人页的信息组织方式，但视觉上保持 WorthMatch 的简洁产品感。

顶部区域：

- 头像。
- 昵称。
- 城市/身份/兴趣。
- 核心标签。
- 编辑档案入口。

核心模块：

- 档案完整度。
- 参与过。
- 收藏。
- 浏览记录。
- 好友。

设置列表：

- 个人档案。
- 活动足迹。
- 收藏。
- 添加好友方式。
- 好友权限。
- 隐私设置。
- 通知设置。
- 账号与安全。

需要支持的设置方向：

- 头像、昵称、标签。
- 公开介绍。
- 当前想找的搭子。
- 资料可见性。
- 活动足迹可见性。
- AI 记忆是否用于匹配。

## 6. 核心业务闭环

WorthMatch 的核心不是刷人，而是通过具体事情建立关系：

1. 用户在 AI Agent 中表达模糊需求。
2. Agent 将需求结构化为搭子卡片。
3. 卡片可以发布到探索页或用于系统匹配。
4. 用户加入活动或匹配成功后进入消息页。
5. 用户在聊天中逐步确认边界、时间、地点和关系节奏。
6. 行为和反馈沉淀到“我的”档案和 AI 记忆。

## 7. 后端对接对象

前端需要预留的数据对象：

- UserProfile：用户档案。
- AgentThread：AI 对话。
- AgentCard：Agent 生成的需求卡。
- Activity：探索页活动/帖子/功能。
- Match：匹配关系。
- Conversation：聊天会话。
- Message：消息、系统提示、位置卡、文件卡。
- Permission：资料可见权限。
- History：浏览、收藏、参与记录。

后端 MVP 可以先做：

- 保存用户档案。
- 保存 Agent 生成的卡片。
- 保存探索页活动。
- 保存聊天关系和消息。
- 保存权限字段。

AI 服务需要重点支持：

- 从自然语言提取结构化需求。
- 生成可发布卡片。
- 生成开场白。
- 总结用户偏好和边界。
- 在匹配前解释为什么适合。
